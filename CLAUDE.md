# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A Quarto website (Devon Allies' personal site and data portfolio) published via GitHub Pages from the committed `docs/` folder (`.nojekyll` present) at https://devonallies.co.za/ (custom domain; `CNAME` in the project root is copied into `docs/` via `project.resources`, and GitHub redirects the old devonallies.github.io/DataAnalysisPortfolio/ address). There is no build system beyond Quarto and no test suite.

## Environments

- **R: renv** (`renv.lock`, `renv/`). `.Rprofile` activates it automatically. Restore with `Rscript -e 'renv::restore()'`. Includes Bioconductor packages (`ballgown`, `genefilter`).
- **Python: uv** (`pyproject.toml`, `uv.lock`). Create the env with `uv sync`; add packages with `uv add <pkg>`.
- `.Rprofile` sets `RETICULATE_PYTHON` to `<project root>/.venv/bin/python`, so `{python}` chunks run under knitr+reticulate use the uv env. Quarto starts R from the project root (so `.Rprofile` loads) even for pages in subfolders, while each chunk's working directory is the page's own folder.
- Several pages load packages via `lapply(packages, library, character.only = TRUE)`, which renv's dependency scan can't see. When adding a package that way, also add a `library()` line to `scripts/r_dependencies.R`, then run `renv::snapshot()`.

## Commands

```bash
quarto render projects/<name>/index.qmd   # render one page (preferred; see below)
python3 -m http.server 4322 -d docs        # serve docs/ locally as plain files (see caveat below)
uv run python scripts/fetch_publications.py   # refresh _data/publications.json
uv run python scripts/build_tutorial_data.py  # rebuild tutorials/data/ from local full data
uv run python scripts/simulate_plasma_cytokines.py  # rebuild tutorials/data/bal_plasma_cytokines.xlsx
uv run python scripts/build_excel_capture_example.py # rebuild the Excel article's example workbook
uv run python scripts/strip_drafts.py         # before committing: drop drafts and redirect pages from docs/search.json and sitemap.xml
Rscript scripts/build_clean_data.R            # rebuild the *_clean.csv files from the messy tutorial data
```

Prefer rendering pages one at a time over a bare `quarto render`: `chrx-rnaseq` and `tb-bal-cytokines` need local-only data, and `r-python-workflow` downloads from Kaggle, so a full render fails anywhere that data is missing. Rendered output in `docs/` is what gets deployed, so re-render and commit `docs/` alongside any `.qmd` change.

## Structure

- `_quarto.yml` — site config: `output-dir: docs`, cosmo + brand theme, `grid.body-width: 960px`, navbar (Home / Projects / Tutorials / Publications & Writing / Resources / About Me / Contact), site-wide `acronyms` filter, `site-url` (sitemap) and `open-graph` and `twitter-card` (link previews; X needs its own `twitter:card` tags, `summary_large_image`, `@CompBioSeq`).
- `projects/<name>/` — one folder per project, all with the same layout: `index.qmd` (URL `/projects/<name>/`), `references.bib`, `images/` (thumbnail + figures), `data/` (inputs). Chunks run from the page's folder, so code reads `data/...` relative paths. Every project uses the shared citation style `../../assets/csl/harvard-anglia-ruskin-university.csl`. Each page lists its pre-2026-11-13 address under `aliases:`, which makes Quarto write a redirect page there; keep these so old links and Google's index keep working.
- Project data: only `covid19-blood-counts/data/` and `tb-global-trends/data/` are committed (explicit `!` exceptions in `.gitignore`); every other `data/` is local-only. `chrx-rnaseq` and `tb-bal-cytokines` need their local data to render.
- `index.qmd` — home page. Its "Featured projects" grid lists specific project files by hand (`listing.contents`). It also carries the Google Search Console verification meta tag (`include-in-header`); don't remove it.
- `projects.qmd` — grid listing over `projects/`, sorted by `date desc`. Its category list sits in the left column: Quarto always puts listing categories in the right margin, so the page sets `toc-location: left` and `body-classes: categories-left`, and `styles.css` moves the margin sidebar there on wide screens. Front matter (`title`, `date`, `description`, `image`, `categories`) drives each card, so new projects need these set and the `image` must exist.
- `tutorials.qmd` — two tracks, each a section with its own banner, "About this track" box, collapsible group of cards (closed by default, summary "Latest: …"; `assets/js/toc-groups.js` lists them in "On this page") and "Coming next": **Bioinformatics on the command line** first (`tutorials/command-line/<slug>/index.qmd`, numbered by `series-part`; the user's degree is Bioinformatics & Computational Biology) and **Data science** (R and Python; `tutorials/0N-*/*.qmd`, numbered by each tutorial's `order` field; `tutorials/_metadata.yml` sets shared options). The cards are built by R code from each tutorial's front matter (not a Quarto listing), so tutorials dated in the future are drafts: hidden from the cards and shown under "Coming next" without a link. The R track's "Coming next" items are written by hand in the page. `tutorials/command-line/_metadata.yml` makes external links open in a new tab and sets `tutorials/images/command-line-series.jpg` as the link-preview image. Parts 1 and 2 were first published under `writing/` and keep `aliases:` redirects there.
- `resources.qmd` — each section (Free books, Package documentation, …) sits in a collapsible `<details class="pub-group">` with a one-line summary of what's inside (no counts), closed by default; clicking a section in "On this page" opens it. Card titles are small headings (`### … {.pub-title}` / `{.resource-title}`, styled like plain text in `styles.css`) so `assets/js/toc-groups.js` can list each card under its section in "On this page" while that group is open (Quarto itself leaves headings inside cards out of the TOC); `publications.qmd` uses the same script. Inside are hand-written card grids (Quarto `.grid` with `.g-col-*` columns; `.resource-grid`/`.resource-card` in `styles.css`): free books as two-column `.pub-card`s, each with a "Goes with" link to the matching tutorial, article or project, then three-column cards for package documentation, tools and bioinformatics links. External links open in a new tab (`link-external-newwindow: true`, set on this page only). Only list things that are free to read or use; check each link works before adding it. When a new tutorial or article uses a book or package, add it here too.
- `tutorials/data/` — small simulated BAL dataset, committed on purpose (`!tutorials/data/` and `!docs/tutorials/data/` exceptions) and copied into `docs/` via `project.resources` for the download buttons. Built by `scripts/build_tutorial_data.py` from the local, gitignored full study in `data/bal/bal-project/data/` (drops names/birth dates; `Age` comes from the cleaned baseline table). The raw Excel files are deliberately messy and the tutorial text describes those quirks, so regenerate with care. `scripts/build_clean_data.R` turns them into `bal_metadata_clean.csv` (one row per participant) and `bal_cell_counts_clean.csv` (one row per visit) for the statistics tutorials; its metadata rules match Tutorial 3 (cleaning), so change both together, and rerun it whenever the messy files are regenerated. Rows that contradict each other are flagged in `review_*` columns, not changed.
- `writing/<name>/` — articles on this site (`index.qmd` + `references.bib`, shared CSL), e.g. `choosing-statistics-for-cytokine-data`. `publications.qmd` lists every `writing/*/index.qmd` in its "On this site" section from each article's own front matter (`title`, `subtitle`, `date`, `categories`, and `series`/`series-part` if any), so a new article needs those set. The page has "On this page" on the left, and each group of cards (papers, articles newest first, Medium) sits in a collapsible `<details class="pub-group">`, closed by default, whose summary names only the latest item (no counts). Multi-part tutorial series are listed on the Tutorials page, not here. `writing/_metadata.yml` sets `link-external-newwindow: true` for every article (links to other sites open in a new tab); the Publications and Resources pages set it themselves. Articles dated in the future are treated as drafts: both lists (and the home page's "Latest" card) skip them until that date, so a draft can sit in `writing/` safely, but don't commit its `docs/` output (it would still appear in site search) until it's published. The cytokine article reads `tutorials/data/bal_plasma_cytokines.xlsx`, simulated by `scripts/simulate_plasma_cytokines.py` (every value invented; the effects are simulation settings) and joined to `bal_metadata_clean.csv`. Its text quotes specific results, so re-check the numbers if the simulation changes. It describes the user's own ongoing master's approach to out-of-range values (cytokines with >40–50% OOR/missing left out; OOR values left out of tests, no imputation) as one approach that isn't universally accepted; keep that framing.
- **Tutorial series navigation:** a multi-part tutorial joins a series with `series: <key>` and `series-part: <n>` in its front matter, plus `filters: [<path>/assets/lua/series.lua]`. The `SERIES` table at the top of `assets/lua/series.lua` gives each series' name, folder and label: `command-line` ("Bioinformatics on the command line", `tutorials/command-line`, "Part") and `data-science` ("Data science", `tutorials`, "Tutorial"; Tutorials 1–4, `series-part` = `order`). It finds every `*.qmd` one folder below the series folder and adds three things: a collapsible `<details class="series-box">` under the title (raw HTML, so it doesn't depend on Quarto's callout processing), an "In this series" side panel that `assets/js/series-panel.js` moves into the empty right-hand margin column on wide screens (hiding the box there), and previous/next links before the References heading. Future-dated parts show as "coming soon", unlinked, and the filter warns if a part is dated before the part above it. Command-line parts use real public TB data kept on the user's DATA drive (`/run/media/devon/DATA/cli-series/`), so their outputs are static text saved from real runs, not executed at render time. Re-rendering Tutorial 4 changes its jittered figures, so restore `fig-macrophages-1.png` and `fig-neutrophils-1.png` from git afterwards. Link-preview images: `tutorials/_metadata.yml` sets `images/tutorial-series.jpg` for the Data science track; `tutorials/command-line/_metadata.yml` overrides it with `command-line-series.jpg`.
- **Share buttons:** `assets/js/share.js` adds Email, X, WhatsApp, LinkedIn and Copy link buttons under the title and before the references on every article and tutorial. It's switched on by `include-after-body` in `writing/_metadata.yml` and `tutorials/_metadata.yml`, and links always point to https://devonallies.co.za plus the page's path. For a published tutorial whose code shouldn't re-run (Tutorial 4's jittered figures), the script line can be added to its `docs/` HTML after `</div> <!-- /content -->`, matching where Quarto puts it.
- `contact.qmd` — contact form posted to **FormSubmit** (formsubmit.co, no account) at `devon.lee.allies@gmail.com`, like the separate Naturally Nella site. An inline script sends it to the `/ajax/` endpoint and shows a status; without JavaScript it posts normally and `_next` returns to `contact.html?sent=1`. A `_honey` field catches bots; `?topic=tutorial` pre-selects a topic. FormSubmit only delivers after the activation link in its first email is clicked.
- `publications.qmd` ("Publications & Writing") — lists the `writing/` articles (see above) and renders `_data/publications.json` (no network at render time). `scripts/fetch_publications.py` builds it from ORCID (0000-0001-8928-4334), Crossref and the Medium RSS feed (@alliesdl); `OVERRIDES` corrects bad ORCID metadata. The page matches the user by surname (`Allies D` / `Allies DL`).
- `assets/` — shared `css/theme.scss` (site colours: deep teal `#0F4C5C` with orange accent `#E36414`; Bootstrap variables plus navbar, banner and heading rules), `css/styles.css` (component styles: cards, timeline, publications), `images/me.jpeg` (About photo), `images/og-card.jpg` (default link-preview card, 1200×628, set as `website.image`), `csl/`. The bright orange fails text contrast on white (3.4:1), so use it only for decoration; use `$orange-dark` `#B34A0C` for orange text. No page should set its own `theme:`, so every page shares the palette. There is a light and a dark theme (navbar toggle; `respect-user-color-scheme: true` follows the visitor's system setting): `_quarto.yml` layers `css/theme-dark.scss` on top of `theme.scss`, whose variables are all `!default` so the dark file can replace them. Style new components with `var(--bs-...)` colours (as `styles.css` does) or the role variables in `theme.scss`, not hard-coded hex, so they work in both themes.
- `guides/<name>/` — printable PDF guides (Quarto + Typst, `format: typst`), e.g. `choosing-a-statistical-test` (goes with Tutorial 4). Excluded from the site build by `"!guides/"` in `project.render`; render each one explicitly with `quarto render guides/<name>/<name>.qmd`, which writes the PDF next to the source, and `project.resources` (`guides/*/*.pdf`) copies it into `docs/` on the next page render. Commit both the source and the PDF. They use the shared CSL in `assets/csl/`.
- `scripts/` — helper scripts (not rendered). `data/` (root) — local-only full datasets and `data/archive/`; gitignored, and excluded from rendering by `project.render` in `_quarto.yml` (it can hold `.md`/`.qmd` files from other projects that must not become pages). `linkedin/` — local resumes; gitignored, never commit.
- `_extensions/rchaput/acronyms/` — vendored Lua filter. Shared acronyms live in `acronyms.yml`; pages can add their own under `acronyms.keys` (see `tb-bal-cytokines`). Use `{{< acr KEY >}}` in text.

## Rendering caveats

- The navbar and stylesheet links are baked into every page's HTML, so changing `website:` or `format:` in `_quarto.yml` means re-rendering every page. For a navbar-only change (adding or reordering items), it's safer to render one simple page (e.g. `contact.qmd`) and apply the identical `<li class="nav-item">` change to the other `docs/**/*.html` files with a script, then check every page's menu order; that avoids re-running analyses whose outputs shift (see below).
- Each render with changed theme/layout settings writes a new hashed `docs/site_libs/bootstrap/bootstrap-*.min.css`; delete ones no `docs/**/*.html` references.
- Every page should have a `description`. On the main pages it's hidden visually via `body-classes: hide-description` (CSS in `assets/css/styles.css`) and used only for search and previews.
- **Don't preview with `quarto preview`.** Even with `--no-render`, it re-renders a page when it's opened in the browser, using an out-of-date cached copy of the source, and overwrites the fresh render in `docs/` (this published stale pages twice). Serve `docs/` as plain files instead (`python3 -m http.server 4322 -d docs`; the embedded IGV viewer needs a server with HTTP range requests). Before committing, check that the rendered HTML contains the change.
- **Full-site renders re-run every page.** `tb-global-trends` fits an unseeded model, so a re-render changes its printed results and figures, and Tutorial 4's jittered figures change too. After a full render (e.g. for a navbar change), restore those outputs from git and keep only the navbar change, so published results don't shift.
- **Older projects show progression on purpose.** The February 2026 projects (`covid19-blood-counts`, `tb-global-trends`, `r-python-workflow`) are kept as originally written, so the site shows how the user's work has grown. Each has a "Looking back (November 2026)" callout at the top (`.looking-back`) noting what they'd do differently. Don't polish their analysis, code or writing style; only fix things that look broken (typos, mislabelled elements). `tb-bal-cytokines` is unfinished and carries a "Work in progress" callout (`.in-progress`); remove it when the classifier is added. The About page's "My journey" timeline links each stage to its project; add new projects there too, at the top. Both About timelines (My journey and Education) are ordered most recent first; keep them consistent.
- Most projects have no `date` field and `chrx-rnaseq` uses `date: today`, so the `date desc` sort on the projects listing is unreliable.
- Some pages (Databricks pipelines, credit risk) are write-ups only: the code lives in separate GitHub repos linked from the page.
