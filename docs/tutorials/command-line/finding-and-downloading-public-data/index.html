Finding and downloading public sequencing data

From a paper to verified FASTQ files on your disk, with Entrez Direct, the European Nucleotide Archive and md5sum

Command line
Bioinformatics
Tuberculosis
How to find public sequencing data from the command line and download it safely: searching PubMed with Entrez Direct (esearch, efetch, xtract), finding a study’s accession in the paper, getting the run table from the European Nucleotide Archive, choosing runs with awk and sort, downloading FASTQ files and a reference genome, and checking every file with md5sum.

Most published sequencing studies deposit their raw reads in a public archive, free for anyone to download and re-analyse. That makes them ideal for learning: real data, with a paper that explains how it was collected. The hard part for a beginner is getting from the paper to the right files, and knowing the files arrived intact.

This article does that from the terminal, start to finish, for the data used in the rest of this series:

  1. Search PubMed for the study with Entrez Direct.
  2. Find the study’s accession number in the paper.
  3. Get the list of sequencing runs from the European Nucleotide Archive (ENA).
  4. Choose runs and download them, with the reference genome.
  5. Check every file with md5sum and record what you downloaded.

It uses the commands from Part 1: pipes, cut, sort, awk and loops over lines.

TipBefore you start
  • First time: open a terminal and work through the sections in order. Section 1 installs Entrez Direct, and section 3 makes the project folder, ~/tb-project, that this and every later part works in.
  • Coming back in a new terminal? Go back into the project folder and switch the tools on again before running anything:
cd ~/tb-project
micromamba activate edirect
export OPENSSL_CONF=~/.openssl-eof.cnf   # only if you needed the fix in section 1

Every command here uses paths relative to ~/tb-project (metadata/, raw/), so run them from there. pwd shows where you are.

NoteAbout the output

Every output shown was saved from a real run on 20 November 2026, with Entrez Direct 26.0. Searches of live databases change over time, so yours may find more results than mine; the study and its files won’t change.

Where public sequencing data lives

Three archives share the world’s raw sequencing data, mirroring each other daily as the International Nucleotide Sequence Database Collaboration: NCBI’s Sequence Read Archive (SRA) in the United States, the European Nucleotide Archive (ENA) in the UK, and the DNA Data Bank of Japan. A study submitted to any one appears in all three, under the same accession numbers:

Papers normally give the project accession; the files you download belong to runs.

1. Search PubMed with Entrez Direct

Entrez Direct (EDirect) is NCBI’s set of command-line tools for searching its databases (Kans, 2013): PubMed, the nucleotide database, SRA and dozens more. It’s on Bioconda, so with micromamba (see Part 1):

micromamba create -n edirect entrez-direct
micromamba activate edirect

(Activate the environment rather than using micromamba run: the commands below are joined by pipes, and micromamba run only applies to the first command in a pipe. See the warning in Part 1.)

Three commands do most of the work, joined by pipes:

  • esearch runs a search and remembers the results;
  • efetch downloads the records, in the format you ask for;
  • xtract pulls chosen fields out of the records into a table.

Start with a search. PubMed’s usual search syntax works: quotes for exact phrases, AND, OR and brackets:

esearch -db pubmed -query 'tuberculosis AND "Western Cape" AND "whole genome sequencing" AND (XDR OR "extensively drug")'
<ENTREZ_DIRECT>
  <Db>pubmed</Db>
  <Query>tuberculosis AND "Western Cape" AND "whole genome sequencing" AND (XDR OR "extensively drug")</Query>
  <Count>7</Count>
  <Step>1</Step>
  <Elapsed>11</Elapsed>
</ENTREZ_DIRECT>

Seven papers match. On its own, esearch prints only this summary; the results wait on NCBI’s server for the next command. Pipe them into efetch for a short summary of each paper (-format docsum), and into xtract to keep four fields:

esearch -db pubmed -query 'tuberculosis AND "Western Cape" AND "whole genome sequencing" AND (XDR OR "extensively drug")' \
  | efetch -format docsum \
  | xtract -pattern DocumentSummary -element Id PubDate Source Title
21110864    2010 Nov 26 BMC Genomics    The non-clonality of drug resistance in Beijing-genotype isolates of Mycobacterium tuberculosis from the Western Cape of South Africa.
28109869    2017 Apr    Lancet Respir Med   Outcomes, infectiousness, and transmission dynamics of patients with extensively drug-resistant tuberculosis and home-discharged patients with programmatically incurable tuberculosis: a prospective cohort study.
34780706    2022 Apr    Lancet Infect Dis   Assessment of epidemiological and genetic characteristics and clinical outcomes of resistance to bedaquiline in patients treated for rifampicin-resistant tuberculosis: a cross-sectional and longitudinal study.
35471145    2022 Apr    Microb Genom    Transmission, distribution and drug resistance-conferring mutations of extensively drug-resistant tuberculosis in the Western Cape Province, South Africa.
39338491    2024 Sep 2  Microorganisms  A Genome-Focused Investigation Reveals the Emergence of a Mycobacterium tuberculosis Strain Related to Multidrug-Resistant Tuberculosis in the Amazon Region of Brazil.
40980012    2025    Front Cell Infect Microbiol Population structure and emergence of resistance to new and repurposed drugs in XDR-TB: insights from a 10-year genomic study in the Western Cape, South Africa review.
41809859    2026 Mar    ERJ Open Res    Multicentre field evaluation of Xpert MTB/XDR in sub-Saharan Africa.

xtract -pattern DocumentSummary starts a new row for each record, and -element lists the fields to keep, separated by tabs. The output is an ordinary table, so sort, grep and cut all work on it.

The fourth paper is the one this series uses (Oostvogels et al., 2022). Its first column is its PubMed ID, 35471145.

WarningIf every EDirect command fails with “curl: (56)”

On recent Linux systems you may see this for every command:

curl: (56) OpenSSL SSL_read: OpenSSL/3.5.5: error:0A000126:SSL routines::unexpected eof while reading, errno 0
 ERROR:  curl command failed ( … ) with: 56

EDirect 26.0 asks NCBI’s servers for an old style of connection (HTTP/1.0), which they close in a way that newer OpenSSL versions treat as an error, so EDirect throws away a reply that had arrived intact. A small OpenSSL setting tells it to accept that. Save these lines as ~/.openssl-eof.cnf:

~/.openssl-eof.cnf
openssl_conf = openssl_init
[openssl_init]
ssl_conf = ssl_sect
[ssl_sect]
system_default = system_default_sect
[system_default_sect]
Options = IgnoreUnexpectedEOF

and point OpenSSL to it before running EDirect, in the same terminal:

export OPENSSL_CONF=~/.openssl-eof.cnf

It only affects the terminal you set it in, and only relaxes that one check.

2. Find the data in the paper

The paper’s record lists its identifiers: the DOI, and, because it’s open access, a PubMed Central (PMC) ID, which leads to the full text. xtract can pull out both:

efetch -db pubmed -id 35471145 -format xml \
  | xtract -pattern PubmedArticle -element MedlineCitation/PMID \
      -group PubmedData/ArticleIdList \
      -block ArticleId -if @IdType -equals doi -element ArticleId \
      -block ArticleId -if @IdType -equals pmc -element ArticleId
35471145    10.1099/mgen.0.000815   PMC9453078

Three identifiers for one paper: the PubMed ID (35471145), the DOI (10.1099/mgen.0.000815) and the PMC ID (PMC9453078). The -block … -if @IdType -equals doi lines keep only the ID of the type asked for. -group PubmedData/ArticleIdList matters too: the record also contains the paper’s reference list, with an ID for every paper it cites, and without that line xtract returns all of their DOIs as well. Seeing more than you expected is a common first experience with xtract, and a reason to check results by eye.

Studies state where their data is, usually in a “Data summary” or “Data availability” section. Download the full text from PubMed Central, using the PMC ID without its PMC prefix, and search it for project accessions:

efetch -db pmc -id 9453078 -format xml > paper.xml
grep -o "PRJ[A-Z]*[0-9]*" paper.xml | sort | uniq -c | sort -rn
      4 PRJEB35725
      4 PRJEB14199
      3 PRJEB43283

grep -o prints each match on its own line, and sort | uniq -c counts them, as in Part 1. Three projects are named. The paper’s text explains them: PRJEB14199 and PRJEB35725 hold genomes published by earlier studies, and the next sentence names the third:

Newly published whole genome sequences of Mtb genomes are published under accession number PRJEB43283 on the European Nucleotide Archive.

So PRJEB43283 is the new data.

TipWhy read the paper?

NCBI can link a paper to its data with elink, but only when the submitters connected the two, which many don’t. Here elink from the paper finds no data at all. The paper’s own data statement is the reliable source, and it also tells you which data is new and which is re-used.

3. Get the run table

Set up a project folder

From here on, the commands save files: the run table, the reads, the reference genome. Make one folder for the whole project, move into it, and check where you are:

mkdir -p ~/tb-project
cd ~/tb-project
pwd
/home/you/tb-project

Run every command in the rest of this article, and in the parts after it, from this folder. The commands use relative paths such as metadata/ and raw/, which mean “inside the folder I’m in now” (see paths in Part 1). Run them from somewhere else and the files are created there instead, or can’t be found.

If a command later says No such file or directory, run pwd first. If you’re not in ~/tb-project, cd ~/tb-project takes you back.

Download the run table

Every project has a run table: one row per sequencing run, with its sample, instrument, size, download links and checksums. ENA serves it from a web address that curl can fetch directly, choosing the columns with fields=:

mkdir -p metadata
curl -s "https://www.ebi.ac.uk/ena/portal/api/filereport?accession=PRJEB43283&result=read_run&fields=run_accession,instrument_model,read_count,base_count,fastq_md5,fastq_ftp&format=tsv" \
  -o metadata/PRJEB43283_runs.tsv

The address is in quotes because it contains &, which the shell would otherwise treat as an instruction. Look at what arrived:

wc -l metadata/PRJEB43283_runs.tsv
head -n 2 metadata/PRJEB43283_runs.tsv
361 metadata/PRJEB43283_runs.tsv
run_accession   instrument_model    read_count  base_count  fastq_md5   fastq_ftp
ERR8025410  Illumina NovaSeq 6000   2128470 321398970   21691a7fd0612f88485325cc79ea24d8;0f8c3c594a6613a6548f995e337f6ab6   ftp.sra.ebi.ac.uk/vol1/fastq/ERR802/000/ERR8025410/ERR8025410_1.fastq.gz;ftp.sra.ebi.ac.uk/vol1/fastq/ERR802/000/ERR8025410/ERR8025410_2.fastq.gz

A header plus 360 runs. Each paired run has two FASTQ files, so the last two columns hold two values separated by ;: one checksum and one link per file. Count the instruments with the pattern from Part 1:

tail -n +2 metadata/PRJEB43283_runs.tsv | cut -f 2 | sort | uniq -c
     40 Illumina HiSeq 2000
    320 Illumina NovaSeq 6000

(cut splits on tabs by default, which is what this file uses.)

NoteGetting the table from NCBI instead

EDirect can fetch the equivalent table from SRA with esearch -db sra -query PRJEB43283 | efetch -format runinfo, as comma-separated values. ENA’s version is quicker for large projects, lets you choose the columns, and includes direct download links and checksums, which is why this article uses it.

Choose the runs

For a tutorial, small is good. awk keeps only the NovaSeq runs ($2 is the second column, -F '\t' says the columns are tab-separated), then sort orders them by read count (-k 3,3n: column 3, numerically) and head keeps the four smallest:

awk -F '\t' '$2 == "Illumina NovaSeq 6000"' metadata/PRJEB43283_runs.tsv \
  | sort -t $'\t' -k 3,3n | head -n 4 > metadata/chosen_runs.tsv
cut -f 1-4 metadata/chosen_runs.tsv
ERR8025410  Illumina NovaSeq 6000   2128470 321398970
ERR8025420  Illumina NovaSeq 6000   2276564 343761164
ERR8025690  Illumina NovaSeq 6000   2321424 582677424
ERR8025744  Illumina NovaSeq 6000   2547056 639311056

$'\t' is how to write a tab character for sort. ENA’s read_count here counts both reads of each pair, so ERR8025410’s 2,128,470 reads are 1,064,235 pairs. Section 5 checks this after downloading.

4. Download the files

The download links are in column 6, two per run, separated by ;. First, look at them on their own: cut takes column 6, and tr ';' '\n' swaps each ; for a new line, so every link gets a line of its own:

cut -f 6 metadata/chosen_runs.tsv | tr ';' '\n' | head -n 3
ftp.sra.ebi.ac.uk/vol1/fastq/ERR802/000/ERR8025410/ERR8025410_1.fastq.gz
ftp.sra.ebi.ac.uk/vol1/fastq/ERR802/000/ERR8025410/ERR8025410_2.fastq.gz
ftp.sra.ebi.ac.uk/vol1/fastq/ERR802/000/ERR8025420/ERR8025420_1.fastq.gz

Eight lines in all, one per file. To download them, send those lines into a loop that runs curl once per line:

cut -f 6 metadata/chosen_runs.tsv | tr ';' '\n' | while read -r url; do
  echo curl -sS -o "raw/$(basename "$url")" "https://$url"
done | head -n 2
curl -sS -o raw/ERR8025410_1.fastq.gz https://ftp.sra.ebi.ac.uk/vol1/fastq/ERR802/000/ERR8025410/ERR8025410_1.fastq.gz
curl -sS -o raw/ERR8025410_2.fastq.gz https://ftp.sra.ebi.ac.uk/vol1/fastq/ERR802/000/ERR8025410/ERR8025410_2.fastq.gz

How the loop works:

  • while read -r url creates the variable url. Each time round the loop, read takes the next line coming through the pipe, one of the links above, and stores it in url; when there are no lines left, the loop ends. So you don’t set url yourself: the first time round it holds the first link, the second time the second, and so on. (-r keeps any backslashes in the line as they are.)
  • $url then means “the link for this time round”. basename "$url" keeps just the file name from its end (ERR8025410_1.fastq.gz), and -o "raw/…" saves the download under that name in raw/.
  • "https://$url" adds the protocol: the links say ftp.sra.ebi.ac.uk without one, and the same server answers on https://.
  • -sS hides curl’s progress bar but still shows errors.
  • echo in front of curl prints each command instead of running it, so you can check them first: a “dry run”.

When the commands look right, remove the echo and download for real:

mkdir -p raw
cut -f 6 metadata/chosen_runs.tsv | tr ';' '\n' | while read -r url; do
  curl -sS -o "raw/$(basename "$url")" "https://$url"
done
ls -lh raw/
96M ERR8025410_1.fastq.gz
97M ERR8025410_2.fastq.gz
101M ERR8025420_1.fastq.gz
103M ERR8025420_2.fastq.gz
206M ERR8025690_1.fastq.gz
222M ERR8025690_2.fastq.gz
213M ERR8025744_1.fastq.gz
232M ERR8025744_2.fastq.gz

(ls -lh prints more columns; only the size and name are shown here.) About 1.2 GB in all, a few minutes on a good connection.

The reference genome

Analyses compare reads to a reference genome. For M. tuberculosis that’s H37Rv (Cole et al., 1998), GenBank accession NC_000962.3, which efetch downloads from NCBI’s nucleotide database as FASTA:

mkdir -p reference
efetch -db nuccore -id NC_000962.3 -format fasta > reference/H37Rv.fasta
head -n 1 reference/H37Rv.fasta
>NC_000962.3 Mycobacterium tuberculosis H37Rv, complete genome

5. Check the files arrived intact

A download can stop partway without an obvious error, especially on large files. A checksum catches it: a short code computed from every byte of a file, so any change, even one byte, gives a different code. ENA lists the MD5 checksum of every file in column 5 of the run table. md5sum -c compares files against a list in the form checksum path, which paste builds by putting the checksums and file names side by side:

paste <(cut -f 5 metadata/chosen_runs.tsv | tr ';' '\n') \
      <(cut -f 6 metadata/chosen_runs.tsv | tr ';' '\n' | xargs -n 1 basename) \
  | sed 's|\t|  raw/|' > metadata/md5sums.txt
head -n 2 metadata/md5sums.txt
21691a7fd0612f88485325cc79ea24d8  raw/ERR8025410_1.fastq.gz
0f8c3c594a6613a6548f995e337f6ab6  raw/ERR8025410_2.fastq.gz

<( ) hands a command’s output to another command as if it were a file, so paste can join two pipelines column by column. xargs -n 1 basename runs basename on each line, and sed swaps the tab for two spaces and the folder name. Now check:

md5sum -c metadata/md5sums.txt
raw/ERR8025410_1.fastq.gz: OK
raw/ERR8025410_2.fastq.gz: OK
raw/ERR8025420_1.fastq.gz: OK
raw/ERR8025420_2.fastq.gz: OK
raw/ERR8025690_1.fastq.gz: OK
raw/ERR8025690_2.fastq.gz: OK
raw/ERR8025744_1.fastq.gz: OK
raw/ERR8025744_2.fastq.gz: OK

Every file matches. This is what a file cut short looks like, here a copy stopped after the first 50 MB:

raw/ERR8025410_1.fastq.gz: FAILED
md5sum: WARNING: 1 computed checksum did NOT match

Delete it and download it again. (gzip -t file.fastq.gz tests a compressed file even without a checksum list, and reports unexpected end of file for this one, but a checksum also catches damage that leaves the file readable.)

WarningRun the check from the project folder

The paths in md5sums.txt start with raw/, so they only work from ~/tb-project. From inside raw/, every file looks missing, even though nothing is wrong with them:

cd raw
md5sum -c ../metadata/md5sums.txt
md5sum: raw/ERR8025410_1.fastq.gz: No such file or directory
raw/ERR8025410_1.fastq.gz: FAILED open or read
…
md5sum: WARNING: 8 listed files could not be read

../metadata/md5sums.txt finds the list (.. is the folder above), but each path inside it is then looked for as raw/raw/…. cd .. back to the project folder and run it again.

Check the read counts

The run table said ERR8025410 has 2,128,470 reads. Count them in the downloaded file to see what that means. Every read in a FASTQ file takes exactly four lines (Part 3 of this series shows them), so the number of reads is the number of lines divided by four:

zcat raw/ERR8025410_1.fastq.gz | wc -l
echo $(( $(zcat raw/ERR8025410_1.fastq.gz | wc -l) / 4 ))
4256940
1064235

zcat decompresses a .gz file to the screen without changing it, wc -l counts the lines, and $(( )) does arithmetic in the shell. The _1 file holds 1,064,235 reads, and the _2 file holds the same number: their partners. So the run has 1,064,235 read pairs, and ENA’s 2,128,470 counted both reads of every pair. A count that matches the run table is a second sign the download is complete.

6. Record what you downloaded

Months later, you or a reviewer will ask exactly which data went into an analysis. Keep the answer in the project folder, starting with when you downloaded it:

date -Iseconds > metadata/downloaded_on.txt
cat metadata/downloaded_on.txt
2026-11-20T12:46:01+02:00

date prints the current date and time, and -I asks for the international standard format (ISO 8601) to the precision given, here seconds. Read left to right: the date, year first, so it can’t be mistaken for an American month/day order; T separating date from time; the time; and the time zone (+02:00, two hours ahead of UTC, as in South Africa), which makes the moment unambiguous anywhere in the world. > saves it to the file. (-I belongs to the Linux version of date. On macOS, date +%Y-%m-%dT%H:%M:%S%z gives nearly the same result.)

Why this matters for reproducibility

A public archive isn’t frozen. A project can gain runs after its paper is published, and a file can be replaced by a reprocessed version. Someone repeating your analysis later, following the same steps, could download different data without knowing it. The files in metadata/ together pin down exactly what you used:

  • The run table records what the project contained, and chosen_runs.tsv which runs you took and, with the command that made it, how they were chosen.
  • The checksums identify each file exactly. If anyone downloads the “same” files later, md5sum -c metadata/md5sums.txt shows at once whether they are byte-for-byte what you analysed.
  • The date says when, which explains a mismatch: if the checksums no longer match, the archive changed after that date, and the difference is in the data, not in the analysis.

With the run table, the chosen runs, the checksums and the date in metadata/, the folder now records where every file came from, which runs were chosen and how, when, and that they arrived intact:

tb-project/
├── metadata/
│   ├── PRJEB43283_runs.tsv   every run in the study, as ENA listed it
│   ├── chosen_runs.tsv       the four runs used
│   ├── md5sums.txt           checksums for the downloaded files
│   └── downloaded_on.txt     when
├── raw/                      the eight FASTQ files, never edited
└── reference/
    └── H37Rv.fasta

Treat raw/ as read-only from now on: every later step writes new files elsewhere. chmod a-w raw/* removes write permission, so an accidental > or rm fails instead of destroying the data.

Going further

  • More PubMed fields: efetch -format abstract prints readable abstracts; xtract can pull authors, journals and dates from -format xml for a literature table.
  • Many projects at once: the run-table curl command works for any project accession, so a loop over a list of projects builds one combined table.
  • NCBI limits: NCBI restricts how many requests a computer can send per second. A free API key from your NCBI account raises the limit; EDirect uses it automatically when it’s saved as export NCBI_API_KEY=your_key.
  • SRA Toolkit: NCBI’s prefetch and fasterq-dump download runs from SRA in its own format and convert them to FASTQ. Downloading FASTQ from ENA, as here, avoids the conversion step.
